# Telephone

Art-and-code project: a photograph is passed repeatedly through recompression, captioning and
regeneration, and each generation is measured for what survives. Python package in `telephone/`,
site in `web/` (Vite + React 19 + TypeScript, hand-written SVG charts, static JSON export).

## Rules

- Visual design of `web/` is owned by Impeccable only. Its design brief (created by
  `/impeccable init`) is the source of truth. Do not apply other skills' aesthetics.
- The dashboard in `telephone/dashboard/static/` follows the same skill routing as `web/`.
  `PRODUCT.md` holds the product facts, `DESIGN.md` the dashboard's look (Calibration target),
  and `.impeccable/surfaces/telephone-dashboard.md` its direction contract. It is plain HTML,
  CSS and JavaScript modules with no build step: do not add a framework or a bundler to it.
  Sentences about a result are written in `telephone/dashboard/reading.py`, with tests.
- Motion follows `emil-design-eng`. Respect `prefers-reduced-motion`. No scroll-jacking,
  no parallax on photographs.
- Before calling web work done, review changed files with `web-design-guidelines`.
- Site charts are hand-written SVG reading the static JSON export. Never add a chart library.
- Never use AI-generated or stock imagery on the site. The only images are pipeline outputs and
  the author's photographs.
- Python: write a failing pytest first; use mock providers in tests; never call a paid provider
  in tests or CI.
- Anything touching the Anthropic SDK: consult `claude-api`. Do not change model IDs, the spend
  cap or rate limits without asking.
- The deck is generated by the python-pptx builder. Edit the builder, rebuild, then use `pptx`
  only to render and inspect slides. Never hand-edit the `.pptx`.
- `humanizer` applies to prose only. It must never change a number, metric name or citation.
- Do not run Superpowers brainstorming and `/impeccable shape` in the same session; both try to
  lead planning.
